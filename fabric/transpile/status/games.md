## Differences from Go, root-caused

### 1. werewolf: the generated game did not load

- Symptom: `the generated werewolf compiles` failed, and with it all nine
  documents: `GameSpecError: gameFromData: no body for distribute ` (empty
  FnRef).
- Divergence report: none (fails before the replay).
- Cause: werewolf declares no `DistributeComponentToStarterStack` (it has
  no deck); the exporter writes `SetUp.Distribute: ""` (the schema comment
  says every game has one), and the loader resolved `""` as a FnRef. The
  hand-port loader test never saw it because its adapter maps `""` to the
  hand port's own stub.
- Fix (loader, `rules/data.ts`): `""` is `base.GameDelegate`'s stub, which
  throws Go's text, `DistributeComponentToStarterStack was called, but the
  component was not stored in a stack`; `bodies` is not asked for `""`.
  Documented in the calling-convention table.
- Regression: `rules/data.test.ts` "an empty SetUp.Distribute is
  base.GameDelegate's stub, not a FnRef", against the Go vector
  `testdata/base-delegate.vectors.json` (`facadevec/delegate.go`, which
  calls the real Go stub).

### 2. checkers: the component Legal body got a number where it expected a handle

- Symptom: every checkers document and every constructed position failed:
  `TypeError: Cannot read properties of undefined (reading 'components')`
  in `go/api.ts values`, from `checkers_token_Legal` via
  `moves.DefaultComponent`'s defaults (Crown Token, a fix-up proposed after
  every version).
- Cause: two conventions for role `component`. The translator emits a
  values method's receiver as its handle, `(state, t: DynamicRef,
  legalType)` (translator.md, "Signatures by role"); the loader
  (checkers-engine, gaps-2) passed `(state, index, legalType)`, the
  `DeckSpec.componentLegal` shape, so `t` was a number and `t.deck`
  undefined. Only the hand-written stand-in followed the loader's.
- Fix (loader, `rules/data.ts`): the FnRef body now takes the receiver
  handle `{ deck, index }` (the deck the `ComponentLegal` key names);
  `DeckSpec.componentLegal` keeps `(state, index, legalType)` and the
  loader adapts. The translator's shape is the right one: it is how every
  translated values method (`AllNextSpaces`, `Dynamic`, ...) takes its
  receiver, and the translator cannot know the deck statically. The
  stand-in `tokenLegal` in `rules/checkers.test.ts` now takes the handle.
- Regression: `rules/data.test.ts` "a ComponentLegal body gets its
  receiver as the values handle { deck, index }, the translator's shape".
- After the fix: zero differences on the three documents and all
  constructed positions.

|---|---|---|---|
| memory | `memory.(*moveStartHideCardsTimer).Apply` | `package-var-read memory.hideCardMoveName` (moves.go:114) | the hand port's Start Hide Cards Timer `apply` (`games/memory.ts`), in `memory.gen.test.ts` |

Shape: `index.ts` stays purely generated (`<game>Generated()` =
`gameFromData(definition(), bodies)`). Called alone it throws the loader's
`GameSpecError` `gameFromData: no body for <role> <FnRef>`, which names
the pending FnRef (each game has one). Each test asserts that
`<game>Generated()` throws a GameSpecError naming every pending FnRef,
that `bodies(ref)` is undefined for each (so the test fails, telling you
to drop the stand-in, once a body lands), and (checkers) that the pending
list is exactly the definition's FnRefs `bodies` lacks. The test then
loads `gameFromData(definition(), withPendingBodies(bodies, {ref:
stand-in}))`. `TestCheckedInCurrent` (Go) fails if a checked-in game has a
refused function other than these two.

A cleaner shape needs `lib/transpile/files.go` (not mine, see below).

## Judgment calls

1. Both fixes are in the loader, not the translator: the translator's
   output was right in both cases (werewolf has no distribute to
   translate; the component receiver is the translator's general values
   receiver). No translator rule changed, so no new golden.
2. "Register the generated games in front of the hand ports in an
   additional run of the fuzz test": done as an equivalent test, since
   `games/fuzz.test.ts` is not in my files. `generated.testkit.test.ts`
   replays the same checked-in fuzz documents and the same
   `BOARDGAME_FUZZ_DIR` through the same `runFuzzDocument` against the
   generated games, while `fuzz.test.ts` does it against the hand ports;
   one `npm run test:unit` with the variable set checks both.
3. Checkers' stand-in predicate moved to `testing/checkers.ts` (test
   support, Node-only, outside the engine sandbox), with the replay code,
   rather than a `pending.test-support.ts` under `games/` (which the
   sandbox test would scan as engine code). Memory's stand-in is inside its
   test.
4. `TestCheckedInCurrent` had "a checked-in game has no refused function";
   it now requires the refused set to equal `pendingRefused` exactly.
5. Constructed positions run in four slices (each well under 1 s here) to
   stay far from the 20 s per-test timeout.

## Proposed change to `lib/transpile/files.go` (not made)

For a game with refused functions, `Generate` could write into
`bodies.gen.ts` `export const PENDING: readonly string[] = [<FnRefs>];`
and into `index.ts` `export function <game>Generated(extra?: Bodies):
GameSpec` that, when a pending FnRef is not answered by `extra`, throws a
GameSpecError listing all of them (`<game>: pending bodies: ...`), and
otherwise loads `gameFromData(definition(), ref => extra?.(ref) ??
bodies(ref))`. The tests would then pass their stand-ins as `extra`
instead of wrapping `bodies`. Today's shape is already honest (the loader
names the first missing FnRef, and each game has one), so this is a
convenience, uniform for every game.
